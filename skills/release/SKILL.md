# Phase 6 — Release candidate (local)

Follow **core**. Load the stack pack for the release channel. Use the `release-manager`
agent. This phase **prepares and freezes** what will ship; it never uploads, publishes,
provisions, or deploys (the bash guard blocks those commands until phase 7).

1. **Version**: pick the version (semver; build number for mobile). Update version files,
   `specs/60-delivery/changelog.md`, and feature statuses.
2. **Release build** from a clean checkout of the committed tree, with the production build
   configuration (optimized, no debug flags, no dev-only code paths) — per the stack pack.
   Write the exact commands to `scripts/release-build` (or package scripts) so the build is
   repeatable. Signing that needs credentials is a hard stop: the user signs, or provides
   signing set up on their machine.
3. **Verify the release build locally**: install/serve the release build against the local
   environment (local services, seeded data) and run the full test suite, every `FLOW-`
   test, and a smoke pass of the main screens. Record results in the traceability matrix.
4. **Release notes** from shipped features and the changelog (spec-derive skill,
   release-notes recipe).
5. **Assets & policies**: store/hosting screenshots generated by UI tests on the required
   sizes; app name, subtitle, description, keywords (from the vision and glossary); support
   URL; privacy policy and terms **drafts** marked "needs legal review"; store privacy
   declarations from the QA privacy audit.
6. **Environment inventory** `docs/deploy/environments.md`: environments (local, staging,
   production), every configuration variable and secret each needs (names and purpose, never
   values), external services and accounts, domains. `.env.example` lists every variable.
7. **Deployment runbook** `docs/deploy/runbook.md`: target per environment (from the hosting
   ADR), infrastructure definitions (written, not applied), data migrations and their order,
   deploy commands, smoke checks, monitoring to watch, and the **rollback plan**. Mark every
   account, billing, domain, secret, signing, and submission step as user-owned with exact
   instructions.
8. **Freeze**: commit everything and tag the candidate locally `vX.Y.Z-rc.N`; record the
   artifact paths and checksums in `.build-my-app/reports/release-<version>.md`. Any later
   code change needs a new candidate (`rc.N+1`), re-verified from step 3.

## Gate G6
Automated: release build reproducible from the tag; full suite and flows pass against the
release build locally; environment inventory and runbook complete; no `personal-only`
licenses in the release build. Approval: the user approves the candidate and the runbook
(decision kind: release). Then `bma_state.py gate release pass`.
